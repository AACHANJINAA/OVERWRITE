# Render Pipeline

## 목적
이 문서는 `SYSTEM::OVERWRITE`에서 CPU와 GPU/Shader가 각각 어떤 책임을 가져야 하는지 정의합니다.

목표는 렌더링 구조가 커질 때 게임 로직, STL 퍼즐 판정, 입력 처리, 시각 효과가 섞이지 않게 하는 것입니다.

## 기본 원칙
- CPU는 "무엇을 그릴지" 결정합니다.
- GPU/Shader는 "어떻게 보이게 할지" 처리합니다.
- 게임 상태 변경은 CPU에서만 일어납니다.
- Shader는 화면 표현을 위한 계산만 수행합니다.
- Shader 안에 게임 규칙, 퍼즐 규칙, 선택 판정, 컨테이너 로직을 넣지 않습니다.
- 1차 프로토타입은 고정 파이프라인 스타일 렌더링을 우선하고, Shader 도입 시에도 작은 효과부터 추가합니다.

## CPU 책임

### 게임 상태 관리
CPU는 게임의 실제 상태를 소유합니다.

- 전체 게임 진행 상태
- 현재 선택된 노드
- 각 STL 노드의 상태
  - 정상
  - 버그 발생
  - 선택됨
  - 수리 완료
- 시스템 안정도
- 수리 완료 수
- 승리/실패 여부

### STL 퍼즐 판정
STL 문제와 정답 판정은 반드시 CPU에서 처리합니다.

- 문제 ID 관리
- 증상, 원인, 패치 후보 데이터 관리
- 플레이어가 선택한 패치 판정
- 정답/오답 처리
- 오답 패널티
- 성공 피드백 상태 변경

Shader는 어떤 패치가 정답인지 알면 안 됩니다.

### 입력 처리
사용자 입력은 CPU에서 해석합니다.

- 키보드 입력
- 마우스 클릭
- 마우스 오른쪽 버튼 드래그
- `WASD` 이동
- `F` 상호작용
- ESC 종료
- 노드 선택
- UI 버튼 선택

GPU는 입력 이벤트를 직접 처리하지 않습니다.

### 카메라와 뷰 상태
카메라의 실제 값과 입력 반응은 CPU에서 계산합니다.

- 카메라 위치
- 회전값
- 줌 거리
- view matrix
- projection parameter
- 화면 크기와 aspect ratio

Shader는 CPU가 넘겨준 행렬과 값으로 정점 변환만 수행합니다.

### 렌더링 데이터 준비
CPU는 렌더링에 필요한 데이터를 Shader가 쓰기 쉬운 형태로 정리합니다.

- 그릴 노드 목록
- 그릴 회로 라인 목록
- 노드 위치
- 노드 크기
- 기본 색상
- 선택 여부
- 버그 여부
- 수리 완료 여부
- 점멸 강도
- 시간값
- 카메라 행렬

### UI와 텍스트
UI 내용 결정은 CPU 책임입니다.

- 현재 선택 노드 이름
- 증상 텍스트
- 원인 텍스트
- 패치 후보 텍스트
- 성공/실패 문구
- 시스템 안정도 표시값

Shader는 텍스트 내용을 만들거나 선택하지 않습니다.

### 사운드 이벤트
사운드 재생 조건도 CPU에서 결정합니다.

- 노드 선택음
- 정답음
- 오답음
- 경고음
- 승리음

GPU는 사운드 이벤트를 발생시키지 않습니다.

## GPU/Shader 책임

### 정점 변환
Shader를 사용할 경우 GPU는 CPU가 전달한 행렬을 이용해 정점을 변환합니다.

- local position
- world transform
- view transform
- projection transform
- clip space 변환

카메라 값 자체를 결정하지는 않습니다.

### 색상 표현
GPU는 CPU가 넘긴 색상과 상태값을 바탕으로 최종 색을 만듭니다.

- 기본 노드 색상
- 버그 노드 붉은색 강조
- 정상 노드 푸른색/청록색 강조
- 수리 완료 노드 안정 색상
- 선택 노드 하이라이트

어떤 색을 사용할지에 대한 기본 의미는 CPU 데이터가 결정합니다.

### 네온/글로우 느낌
Shader는 시각 효과를 담당할 수 있습니다.

- emissive 색상 강화
- pulse 효과
- 시간 기반 밝기 변화
- 선택 노드 외곽 강조
- 버그 노드 점멸
- 회로 라인 흐름 느낌
- 거리 기반 fade
- 간단한 scanline

단, 이 효과는 상태를 바꾸지 않고 보기만 바꿉니다.

### 라인과 노드 표현
GPU는 전달받은 도형을 화면에 보기 좋게 표현합니다.

- 와이어프레임 선 색상
- 선 밝기
- 노드 큐브 색상
- 노드 크기 반영
- 라인 흐름 밝기
- 경고 라인 점멸

라인 연결 관계 자체는 CPU가 만듭니다.

### 시간 기반 시각 효과
GPU는 CPU가 넘긴 시간값을 이용해 반복 효과를 만들 수 있습니다.

- `sin(time)` 기반 pulse
- 경고 점멸
- 데이터 흐름 라인 밝기 변화
- 선택 노드 glow 변화

시간값은 CPU가 전달하고, Shader는 그 값을 표현에만 사용합니다.

## Shader에 전달할 데이터

### 공통 프레임 데이터
프레임마다 한 번 전달할 수 있는 데이터입니다.

```cpp
struct FRAME_RENDER_DATA
{
    float time;
    float delta_time;
    float aspect;
    MATRIX4 view_matrix;
    MATRIX4 projection_matrix;
};
```

현재 프로젝트에는 아직 `MATRIX4`가 없으므로, 도입 전까지는 OpenGL 고정 파이프라인 함수와 `CJ_MathHelper.h`의 보조 함수를 사용합니다.

### 노드 렌더 데이터
STL 노드 하나를 그릴 때 필요한 데이터입니다.

```cpp
struct NODE_RENDER_DATA
{
    VECTOR3 position;
    COLORRGB color;
    float size;
    float pulse;
    int is_bugged;
    int is_selected;
    int is_repaired;
};
```

GPU로 보낼 때 `bool`은 플랫폼과 API에 따라 다르게 처리될 수 있으므로 `int` 또는 `float`로 변환합니다.

### 라인 렌더 데이터
회로 라인 하나를 그릴 때 필요한 데이터입니다.

```cpp
struct LINE_RENDER_DATA
{
    VECTOR3 start;
    VECTOR3 end;
    COLORRGB color;
    float intensity;
    float flow_offset;
    int is_warning;
};
```

라인이 어떤 노드를 연결하는지는 CPU가 정합니다.

### UI 렌더 데이터
텍스트 내용은 CPU가 결정하고, GPU는 필요할 경우 위치와 색상만 표현합니다.

```cpp
struct UI_RENDER_DATA
{
    VECTOR3 position;
    COLORRGB color;
    float alpha;
};
```

1차 프로토타입에서는 GDI 또는 간단한 텍스트 출력 방식을 우선합니다.

## Shader에서 사용하면 안 되는 것

### 게임 규칙
Shader에 아래 내용을 넣지 않습니다.

- 승리 조건
- 실패 조건
- 수리 완료 판정
- 오답 패널티
- 시스템 안정도 감소
- 문제 진행 상태

### STL 퍼즐 로직
Shader는 STL 문제를 몰라야 합니다.

- `std::vector::reserve`가 정답인지 판정
- `erase` 이터레이터 패턴 판정
- `unordered_map` 선택 판정
- 문제 ID별 정답 비교
- 패치 후보 선택 처리

### 입력과 선택 판정
아래 작업은 CPU에서 처리합니다.

- 마우스 클릭 위치 해석
- 3D picking
- 선택 노드 결정
- 버튼 클릭 처리
- 키보드 입력 처리

### 데이터 구조 변경
Shader는 게임 데이터를 변경하지 않습니다.

- 노드 배열 추가/삭제
- 회로 연결 추가/삭제
- 문제 데이터 변경
- 패치 후보 변경
- 시스템 상태 변경

### 사운드와 리소스 관리
Shader는 리소스 생명주기를 관리하지 않습니다.

- 사운드 재생
- 사운드 정지
- 파일 로딩
- 에셋 해제
- Windows 핸들 관리

## 현재 단계 기준

### 1차 프로토타입
현재 1차 기준에서는 Shader 없이도 구현 가능한 고정 파이프라인 스타일을 우선합니다.

- `glBegin(GL_LINES)` 기반 와이어프레임
- `glColor3f` 기반 색상
- `glFrustum` 기반 원근 투영
- CPU에서 노드 상태와 색상 결정

### Shader 도입 시 첫 목표
Shader를 도입한다면 아래 순서로 작게 시작합니다.

1. 단순 색상 Shader
2. 노드 emissive/pulse Shader
3. 경고 라인 flow 효과
4. 선택 노드 highlight
5. 전체 화면 scanline 또는 미세한 화면 효과

Shader 도입은 렌더링 표현을 위한 것이며, 게임 로직 이전이나 대체가 아닙니다.

## 책임 구분 예시

### 버그 노드 표시
CPU:
- 노드가 버그 상태인지 판단합니다.
- 붉은색 기본 색상을 정합니다.
- pulse 강도를 계산하거나 시간값을 넘깁니다.

GPU:
- 붉은색을 더 밝게 보이게 합니다.
- 시간값으로 점멸을 표현합니다.
- 외곽선이나 glow 느낌을 만듭니다.

### 노드 수리 완료
CPU:
- 플레이어 패치가 정답인지 판정합니다.
- 노드 상태를 수리 완료로 변경합니다.
- 색상을 푸른색 계열로 바꿉니다.

GPU:
- 변경된 색상을 화면에 표시합니다.
- 안정된 pulse 또는 fade 효과를 표현합니다.

### 회로 라인 흐름
CPU:
- 어떤 노드와 어떤 노드를 연결할지 정합니다.
- 경고 라인인지 정상 라인인지 정합니다.

GPU:
- 라인 밝기를 시간에 따라 변화시킵니다.
- flow offset으로 데이터가 흐르는 느낌을 냅니다.

## 구현 체크리스트
- 새 게임 상태가 생기면 CPU 데이터 구조에 먼저 추가합니다.
- 화면 효과만 필요한 값이면 render data로 변환합니다.
- Shader에는 최종 표현에 필요한 값만 넘깁니다.
- Shader에서 게임 상태를 추론하거나 판정하지 않습니다.
- 같은 수학식이 반복되면 `0.Engine/CJ_MathHelper.h`에 함수로 분리합니다.
- 렌더링 코드가 게임 판정을 시작하면 Manager 또는 Game 계층으로 옮깁니다.
