# STL Problem Bank

## 목적
이 문서는 `SYSTEM::OVERWRITE`에 들어갈 STL 버그 퍼즐 문제은행입니다.

`TASK_BREAKDOWN.md`는 이 문서의 Problem 번호를 참조해 “어떤 문제를 게임에 구현할지”만 정합니다. 문제의 증상, 원인, 정답 패치, 오답 후보, 시각 연출 기준은 이 파일에서 관리합니다.

## 문제 작성 형식
- Problem ID: 구현과 문서에서 참조할 고정 번호
- 시스템 노드: 게임 안에서 표시될 우주선 시스템
- STL 주제: 다루는 C++/STL 개념
- 증상: 플레이어가 보는 치명적 경고
- 원인: 실제 C++ 개발 실수
- 정답 패치: 플레이어가 선택해야 할 해결책
- 오답 후보: 헷갈릴 수 있지만 현재 상황에는 맞지 않는 선택지
- 성공 피드백: 정답 후 보이는 변화

## 1차 프로토타입 필수 문제

### Problem 001 - 엔진 과열: Vector Reallocation
- 시스템 노드: 워프 엔진 제어부
- STL 주제: `std::vector::reserve`, 재할당, 복사 비용
- 증상: 파티클이 생성될 때마다 워프 엔진 프레임이 순간적으로 멈추고 온도가 상승한다.
- 원인: `std::vector<Particle>`에 100,000개 파티클을 순차 삽입하면서 `reserve()`를 호출하지 않아 재할당과 원소 이동이 반복된다.
- 정답 패치: 대량 삽입 전에 `particles.reserve(100000)`을 적용한다.
- 오답 후보:
  - `particles.clear()`로 벡터를 비운다.
  - `particles.shrink_to_fit()`으로 용량을 줄인다.
  - `std::vector`를 매 프레임 새로 생성한다.
- 성공 피드백: 엔진 노드가 붉은색에서 푸른색으로 바뀌고 프레임 스파이크 경고가 사라진다.

### Problem 002 - 포탑 먹통: Iterator Invalidation
- 시스템 노드: 자동 포탑 타겟 배열
- STL 주제: `std::vector::erase`, 이터레이터 무효화
- 증상: 파괴된 적을 타겟 배열에서 제거하는 순간 포탑 추적 시스템이 멈춘다.
- 원인: `std::vector`를 순회하며 `erase(it)`를 호출한 뒤, 무효화된 기존 이터레이터를 계속 증가 또는 참조한다.
- 정답 패치: `it = targets.erase(it)` 반환값을 받아 다음 유효 위치로 순회를 계속한다.
- 오답 후보:
  - `++it`를 `erase(it)` 직후 그대로 실행한다.
  - `targets.clear()`로 전체 타겟을 삭제한다.
  - 포인터 값을 `nullptr`로만 바꾸고 배열에서는 제거하지 않는다.
- 성공 피드백: 포탑 타겟 라인이 다시 이어지고 크래시 경고가 꺼진다.

### Problem 003 - 레이더 탐색 지연: Linear Search
- 시스템 노드: 장거리 레이더 ID 탐색기
- STL 주제: `std::vector` 선형 탐색, `std::map`, `std::unordered_map`
- 증상: 적 군함 10,000개가 접근하면 레이더 탐색 지연이 급격히 커진다.
- 원인: 적 ID를 찾을 때 `std::vector`에서 매번 `std::find`로 선형 탐색해 `O(N)` 비용이 반복된다.
- 정답 패치: ID 기반 조회 회로를 `std::unordered_map<EnemyId, EnemyData>`로 교체한다.
- 오답 후보:
  - `std::vector`를 계속 사용하고 매번 전체 정렬한다.
  - `std::list`로 바꿔 순차 탐색한다.
  - `reserve()`만 호출하고 탐색 구조는 유지한다.
- 성공 피드백: 레이더 스캔 라인이 짧아지고 탐색 지연 경고가 사라진다.

## 확장 후보 문제

### Problem 004 - 생명유지 산소 누수: Dangling Reference
- 시스템 노드: 생명유지장치 산소 밸브 캐시
- STL 주제: `std::vector` 재할당과 참조/포인터 무효화
- 증상: 산소 밸브 값을 캐시한 뒤 새 밸브가 추가되면 생명유지 수치가 이상하게 흔들린다.
- 원인: `std::vector` 원소의 참조나 포인터를 저장해두었는데, 이후 `push_back()` 재할당으로 주소가 바뀐다.
- 정답 패치: 원소 포인터 대신 인덱스/ID를 저장하거나, 재할당이 없도록 충분히 `reserve()`한 뒤 참조 수명을 제한한다.
- 오답 후보:
  - 참조를 전역 변수에 저장한다.
  - `const`를 붙여 주소 변경을 막는다고 가정한다.
  - `shrink_to_fit()`을 호출한다.
- 성공 피드백: 산소 수치가 안정되고 생명유지 노드의 점멸이 멈춘다.

### Problem 005 - 화물 정렬 폭주: Bad Sort Comparator
- 시스템 노드: 화물 자동 정렬 큐
- STL 주제: `std::sort` 비교 함수의 strict weak ordering
- 증상: 화물 정렬 중 콘솔이 불규칙하게 멈추거나 정렬 결과가 계속 뒤섞인다.
- 원인: 비교 함수가 같은 원소에 대해 일관되지 않은 결과를 반환하거나 `<=`를 사용해 strict weak ordering을 깨뜨린다.
- 정답 패치: 비교 함수가 `a.priority < b.priority`처럼 엄격한 약한 순서를 만족하게 고친다.
- 오답 후보:
  - 비교식에 `<=`를 사용한다.
  - 비교 함수 안에서 랜덤 값을 섞는다.
  - 정렬 전후로 `reverse()`를 추가한다.
- 성공 피드백: 화물 라인이 안정된 순서로 정렬되고 경고음이 줄어든다.

### Problem 006 - 통신 로그 폭주: Unbounded Deque
- 시스템 노드: 통신 로그 버퍼
- STL 주제: `std::deque`, 고정 길이 버퍼
- 증상: 오래된 통신 로그가 계속 쌓여 콘솔 메모리 경고가 증가한다.
- 원인: `std::deque<LogEntry>`에 새 로그만 추가하고 오래된 로그를 제거하지 않는다.
- 정답 패치: 새 로그를 `push_back()`한 뒤 최대 개수를 넘으면 `pop_front()`로 오래된 로그를 제거한다.
- 오답 후보:
  - 매번 `clear()`로 전체 로그를 지운다.
  - `std::vector`로 바꾸고 앞에서 `erase(begin())`를 반복한다.
  - 로그 문자열만 빈 문자열로 바꾼다.
- 성공 피드백: 로그 버퍼 게이지가 제한 범위 안에서 유지된다.

### Problem 007 - 드론 목록 중복: Set vs Vector
- 시스템 노드: 정비 드론 등록부
- STL 주제: 중복 제거, `std::set`, `std::unordered_set`
- 증상: 같은 정비 드론이 여러 번 등록되어 명령이 중복 실행된다.
- 원인: 드론 ID를 `std::vector`에 계속 `push_back()`하고 중복 여부를 확인하지 않는다.
- 정답 패치: 드론 ID 등록을 `std::unordered_set<DroneId>`로 관리한다.
- 오답 후보:
  - 중복 등록 후 출력할 때만 숨긴다.
  - 벡터를 매번 순회하며 중복을 지우되 erase 무효화를 무시한다.
  - 드론 이름 문자열만 비교하고 ID는 무시한다.
- 성공 피드백: 드론 명령 라인이 하나씩만 표시된다.

### Problem 008 - 실드 이벤트 유실: Queue Misuse
- 시스템 노드: 실드 이벤트 처리기
- STL 주제: `std::queue`, FIFO 처리
- 증상: 실드 충격 이벤트가 들어온 순서와 다르게 처리되어 방어막 타이밍이 어긋난다.
- 원인: 순서가 중요한 이벤트를 임의 접근 컨테이너에서 뒤섞어 처리한다.
- 정답 패치: 이벤트 입력은 `push`, 처리는 `front()` 확인 후 `pop()`하는 FIFO 큐로 고정한다.
- 오답 후보:
  - 가장 마지막 이벤트만 처리한다.
  - 매 프레임 이벤트 전체를 정렬한다.
  - 이벤트 벡터 중간 원소를 랜덤하게 삭제한다.
- 성공 피드백: 실드 파형이 입력 순서대로 안정적으로 방출된다.
