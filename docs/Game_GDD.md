# 게임 기획서: SYSTEM::OVERWRITE

## 1. 게임 개요
- 한 줄 소개: 우주선 메인 컴파일러 콘솔의 3D 회로 노드에서 STL 컨테이너 버그를 진단하고 패치해 시스템 붕괴를 막는 C++ 디버깅 퍼즐 게임.
- 장르: 교육형 3D 퍼즐 / 시스템 수리 시뮬레이션.
- 플랫폼: Windows PC.
- 기술 방향: C++ / Win32 API / OpenGL(opengl32) / GDI / XAudio2.
- 예상 플레이 시간: 5~10분의 단일 프로토타입.

## 2. 제작 범위
- 팀 규모: 1인 개발.
- 제작 방식: 작은 task 단위로 기능을 검증하며 확장.
- 최종 제출물: 실행 가능한 경량 프로토타입.
- 구현 가능한 범위 요약: 3D 콘솔 보드, STL 노드 선택, 3개 버그 모듈, 패치 선택 UI, 성공/실패 피드백, 간단한 사운드.
- 용량 목표: 1.44MB 제약을 의식해 외부 대형 에셋 없이 기본 도형, 선, 절차적 효과 중심으로 제작한다.
- 라이브러리 제약: 최종 빌드 용량을 위해 외부 라이브러리는 최대한 참조하지 않는다. 1차 기준은 Windows 기본 API, `opengl32.lib`, `gdi32.lib`, `winmm.lib` 또는 XAudio2 같은 Windows SDK 제공 라이브러리만 사용한다.

## 3. 배경과 상황
- 공간: 우주선 함교 내부의 메인 컴파일러 콘솔.
- 비주얼: OpenGL 네온 와이어프레임 3D. 붉은 버그 노드, 푸른 정상 노드, `GL_LINES` 데이터 흐름, 간단한 글로우 느낌.
- 상황: 엔진, 레이더, 생명유지장치, 포탑이 메모리 버그와 STL 컨테이너 오용으로 과열 또는 다운된다.
- 플레이어 역할: 시스템 수리 엔지니어. 3D 노드 회로를 조사하고 올바른 STL 패치를 적용한다.

## 4. 핵심 플레이
- 플레이어가 가장 자주 하는 행동: 콘솔 보드를 회전/확대하며 붉은 오류 노드를 찾고, 노드를 클릭해 증상과 원인을 읽은 뒤 올바른 패치 스위치를 연결한다.
- 플레이 감각: 기술적 문제를 시각적으로 진단하고 즉시 시스템이 안정되는 느낌.
- 기본 플레이 흐름:
  1. 우주선 시스템 경고가 발생한다.
  2. 플레이어가 붉게 과열된 STL 노드를 선택한다.
  3. 증상, 원인, 패치 후보를 확인한다.
  4. 올바른 패치를 선택하면 노드가 안정화되고 시스템 수치가 회복된다.
  5. 모든 치명적 노드를 수리하면 승리한다.

## 5. 대표 버그 모듈

실제 문제 목록과 확장 후보는 `docs/STL_Problem.md`에서 관리한다. 아래 3개는 1차 프로토타입 필수 문제다.

### Module 01. 엔진 과열 - Vector Reallocation
- 증상: 워프 엔진 가속 시 프레임 드랍과 과열 발생.
- 원인: `std::vector<Particle>`에 대량 요소를 넣지만 `reserve()`를 호출하지 않아 재할당과 복사가 반복된다.
- 정답 패치: `reserve(100000)`을 먼저 연결한다.
- 성공 피드백: 엔진 온도 하락, 프레임 스파이크 제거, 붉은 노드가 푸른색으로 전환.

### Module 02. 포탑 먹통 - Iterator Invalidation
- 증상: 파괴된 타겟을 제거하는 순간 포탑 추적이 크래시한다.
- 원인: `std::vector` 순회 중 `erase(it)` 이후 무효화된 이터레이터를 계속 사용한다.
- 정답 패치: `it = vec.erase(it)` 패턴을 선택한다.
- 대체 패치 후보: 삭제/삽입이 잦은 구조라면 `std::list` 연결을 검토한다.
- 성공 피드백: 포탑 타겟 라인이 정상적으로 재계산된다.

### Module 03. 레이더 탐색 지연 - Time Complexity
- 증상: 적 군함 10,000개 접근 시 레이더 반응이 급격히 느려진다.
- 원인: ID 탐색에 `std::vector` 순차 탐색을 사용해 `O(N)` 비용이 누적된다.
- 정답 패치: ID 기반 탐색 회로를 `std::unordered_map` 또는 `std::map`으로 교체한다.
- 성공 피드백: 레이더 스캔 파형이 짧아지고 탐색 지연 경고가 사라진다.

## 6. 조작
- 카메라 회전: 마우스 드래그.
- 확대/축소: 마우스 휠.
- 노드 선택: 마우스 왼쪽 클릭.
- 패치 선택/연결: 노드 상세 UI에서 패치 버튼 선택 또는 스위치 클릭.
- 취소/닫기: ESC.

## 7. 규칙과 목표
- 성공 조건: 모든 치명적 버그 노드를 올바르게 패치한다.
- 실패 조건: 제한 시간 또는 시스템 안정도 0 도달. 1차 프로토타입에서는 실패 조건을 선택 구현으로 둔다.
- 기본 노드 수: 5개.
- 치명적 버그 노드 수: 3개.
- 오답 패널티: 시스템 안정도 감소 또는 경고음 증가. 1차 구현에서는 시각/사운드 피드백만 우선한다.

## 8. UI
- 메인 화면: 바로 콘솔 보드 진입.
- 플레이 HUD:
  - 시스템 안정도
  - 현재 선택 노드 이름
  - 버그 증상
  - 원인 요약
  - 패치 후보 2~3개
  - 수리 완료 수
- 결과 화면:
  - 성공: 전체 시스템 정상화
  - 실패: 시스템 셧다운
- 안내 문구는 최소화하고, 문제 상황과 패치 선택에 필요한 텍스트만 표시한다.

## 9. 아트/사운드
- 아트 방향: 검은 우주선 콘솔 배경, 청록/푸른 정상 회로, 붉은 오류 회로, 노란 경고 라벨.
- 도형: 큐브, 구체, 라인, 간단한 평면 UI만 사용한다.
- 사운드:
  - 경고음: 짧은 반복 비프.
  - 노드 선택: 낮은 클릭 톤.
  - 오답: 거친 노이즈 톤.
  - 성공: 레트로 8-bit 기계음.
- 사운드는 XAudio2 또는 간단한 절차적 PCM 생성으로 처리한다.

## 10. 구현 우선순위

### 반드시 구현
- OpenGL 창 생성.
- 3D 콘솔 보드 렌더링.
- STL 노드 데이터 구조.
- 노드 선택.
- 노드 상세 정보 UI.
- 3개 STL 버그 모듈.
- 패치 선택과 정답 판정.
- 성공 피드백.

### 가능하면 구현
- 카메라 회전/줌.
- 네온 글로우 느낌의 색상/라인 효과.
- 경고음과 성공음.
- 시스템 안정도 HUD.
- 오답 피드백.

### 시간이 남으면 구현
- 제한 시간.
- 데이터 흐름 파티클.
- 추가 STL 버그 모듈.
- 우주선 함교 배경 라인 디테일.

## 11. 제외할 것
- GLFW, SDL, SFML, GLUT 같은 창/입력 프레임워크.
- GLEW, GLAD 같은 OpenGL 로더 라이브러리.
- ImGui 같은 외부 UI 라이브러리.
- Assimp, stb 계열 같은 외부 에셋/이미지 로더.
- 대형 3D 모델.
- 복잡한 물리.
- 네트워크/멀티플레이.
- 스토리 컷신.
- 외부 대형 이미지/사운드 에셋.
- STL 설명을 길게 읽는 퀴즈 전용 화면.

## 12. 개발 일정
- 1주차: 창 생성, OpenGL 기본 렌더링, 3D 보드와 노드 표시.
- 2주차: 마우스 선택, 카메라 조작, 노드 상세 UI.
- 3주차: 3개 STL 버그 모듈, 패치 판정, 성공/오답 피드백.
- 4주차: 사운드, 연출, 용량 점검, 최종 빌드.
