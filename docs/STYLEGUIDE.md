# Style Guide

## 목적
이 문서는 C++/OpenGL 코드를 작성할 때 따를 기준입니다.

## 공통 원칙
- 초보자도 읽을 수 있게 명확한 이름과 단순한 흐름을 우선합니다.
- 지금 task에 필요한 기능만 작성합니다.
- 성능 최적화는 실제 병목이나 용량 문제가 보일 때 진행합니다.
- 외부 라이브러리 없이 Windows 기본 API와 C++ 표준 라이브러리만으로 해결하는 것을 우선합니다.

## 빌드/의존성 규칙
- 1차 프로토타입에서는 외부 패키지 매니저를 사용하지 않습니다.
- 프로젝트 파일에 외부 include/lib 경로를 추가하지 않습니다.
- 허용 기본 라이브러리는 `opengl32.lib`, `gdi32.lib`, `user32.lib`, `kernel32.lib`, XAudio2 등 Windows SDK 제공 항목으로 제한합니다.
- OpenGL 함수는 기본 제공 범위에서 먼저 해결합니다. 확장 함수가 꼭 필요하면 외부 로더 대신 Windows API로 직접 로드하는 방식을 검토합니다.

## 이름 규칙
- 클래스, 함수, 파일 이름은 역할이 드러나게 작성합니다.
- C++ 파일은 클래스 이름과 같은 기본 이름을 사용합니다.
- enum 값은 대문자 스네이크 케이스를 사용합니다.

## C++ 규칙
- STL 컨테이너 사용 이유가 gameplay와 연결되도록 작성합니다.
- 포인터 소유권이 애매하면 원시 포인터 대신 값, 참조, 인덱스, `std::unique_ptr` 중 적절한 방식을 선택합니다.
- 반복문 중 `erase()`를 사용할 때는 이터레이터 무효화 규칙을 명확히 처리합니다.
- 대량 삽입이 예상되는 `std::vector`에는 필요한 경우 `reserve()`를 사용합니다.

## OpenGL 규칙
- 1차 프로토타입은 선, 기본 도형, 단순 색상을 우선합니다.
- 렌더링 코드는 게임 판정 코드와 섞지 않습니다.
- 화면에 보이는 상태는 데이터 상태에서 계산되게 합니다.

## UI 규칙
- 화면 텍스트는 문제 해결에 필요한 정보만 표시합니다.
- 증상, 원인, 패치 후보는 한 화면에서 읽히게 구성합니다.
- 과도한 설명문보다 선택과 피드백을 우선합니다.

## 에셋 규칙
- 대형 이미지, 폰트, 사운드 파일 사용을 피합니다.
- 필요한 사운드는 절차적 파형 또는 작은 PCM 데이터를 우선합니다.
- 외부 리소스를 추가하면 용량과 출처를 문서에 기록합니다.

## 주석 규칙
- 주석은 기본적으로 한글로 작성합니다.
- 함수에는 어떤 역할인지 짧게 적습니다.
- STL 버그를 설명하는 로직에는 왜 해당 패치가 필요한지 기록합니다.
